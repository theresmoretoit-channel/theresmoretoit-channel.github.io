Why Can't Windows Delete a File That's in Use?

10 min2026-09-22

That message is the visible end of a much stranger question: what does it actually mean to open a file? Because on another computer the same file, open in exactly the same way, deletes without complaining.

First, the useful part. Windows has known which program it is since 2009, and it will tell you — Resource Monitor, CPU tab, Associated Handles, type the filename. Nothing to install. People kept downloading a separate tool anyway, and they had a reason.

The full narration of the video.

0:00The message everybody knows

You try to delete a file. Your computer says it is open in another program. It does not say which one. That message is the visible end of a much stranger question. What does it actually mean to open a file? Because on another computer, the same file, open in the same way, deletes without complaining. Same file. Same action. Two completely different answers.

0:29Which program?

Start with the part that annoys everybody. Which program? Windows knows. It has a kernel object for that open file, and it knows which process owns it. It could name it. So you close things at random. You open Task Manager. You stare at a list of processes and recognise hardly any of them. And for years, the answer really was to download a separate tool. Unlocker came out in 2005, and on Windows XP that was the answer.

1:02Windows already tells you

Then Windows 7 shipped Resource Monitor. The CPU tab. A list called Associated Handles. Type the name of the file. It gives you the program and the process ID. Nothing to install. It has been there since 2009.

Although the separate tools did more than just tell you. They could close the handle and let the file go.

1:30What you fill in when you open a file

Which brings us back to the question. What did that program acquire when it opened the file? Say a video player opens a file called movie.mp4. On Windows, opening a file means filling in two things. The first one is obvious. What do I want to do with it? Read it. Write to it. The second one is the interesting one. What may everybody else do while I have it open? That is a real setting. You say what other programs may do while you have it open. They may read it. They may also write to it. They may delete or rename it. Or nothing at all. Nobody touches this while I am using it.

2:16FILE_SHARE_DELETE

The flag that permits deleting is called FILE_SHARE_DELETE. And Microsoft's documentation adds one line underneath it. Delete access allows both delete and rename operations. So a program that refuses delete sharing has blocked renaming as well.

And if the program that opened the file did not grant it, nothing else can take it.

2:41A sharing violation

Which is why the error is not called file busy. It is called a sharing violation. The answer was sitting in the name of the error the whole time.

2:53On Linux it just works

Now the same thing on a Linux machine. A player opens the video. And you type rm movie.mp4. It works. The video keeps playing.

So what did that program get, if not a hold on the file? This is the whole idea of the video. The name is not the file.

3:16A name is not the file

movie.mp4 is a line in a directory. That line points at an object which holds the actual data. When a program opens the file, what it gets is a reference to the object. Not to the line. So removing the file deletes the line. The object is untouched. The manual page says it in one sentence. The file will remain in existence until the last file descriptor referring to it is closed.

3:48Five hundred megabytes that vanish

Which sounds abstract until you watch it happen. So I made a log file five hundred megabytes long, and left one process holding it open. Then I deleted it. Listing the directory shows nothing at all. The tool that measures the size of the folder says zero. And the tool that measures free space on the disk says five hundred megabytes are still missing. An empty folder. Half a gigabyte gone.

This happens often enough that there is a command just for finding files like this. Deleted, invisible, still on the disk. And the space comes back the moment that one process lets go of the file.

4:34Renaming, and one limit

The same logic covers renaming. Move the file while it is open, and the program never notices. The manual is blunt about that too. Open file descriptors for the old path are unaffected. It was never using the name.

Which has one limit worth knowing about. You cannot overwrite a running program in place. Linux refuses. Text file busy.

What you can do is detach the name and put a new file there. The old process keeps running from an object that no longer has a name. Anything started later gets the new one. Which is the same idea again, proving itself. You can replace many things without touching the object in place.

Which is why Linux can update a program while it is running. You just do not get the new version until you restart it.

So is Windows simply the worse design?

5:36Windows can do the same thing

No. And this is the part that hardly anyone knows. Windows has a way to do exactly the same thing. On NTFS, Windows can ask for a POSIX style delete. Microsoft describes what happens when you use it. The name is removed from the visible namespace. And applications that already had the file open can still use it, even though the name they used to open it is gone. That is the Unix behaviour. On NTFS. Documented by Microsoft.

Both systems can do both things. What differs is the default. What you get when you open a file and never think about it. On Windows, you get a contract. On Unix, you get a reference to an object.

6:31Please restart your computer

Which sounds like a question for programmers, until you have seen this particular message. Please restart your computer to finish installing updates.

Suppose Windows has to replace a library that a running process holds open under the strict contract. It cannot swap the file underneath that process. So something has to let go. Quit the application. Stop the service. Or hand the whole job to the Restart Manager.

7:03The Restart Manager

Which is a real component. It shuts things down in order. Windows applications, then console programs, then services, and Windows Explorer last. Then it starts them up again. And it exists for one reason, which Microsoft states plainly in its own documentation. The primary reason that software installation and updates require a system restart… is that some of the files being updated are currently in use by a running application or service.

7:38But that is not the whole reason

It would be too neat to stop there. Sharing rules are not the only reason a computer asks to restart. A kernel update is different. You cannot swap the kernel underneath itself. Linux has that problem too, although live patching can sometimes avoid a reboot. So the honest version claims less than the satisfying one.

The way Windows treats files in use made some components harder to replace while running, and that contributed. Because every design choice has a consequence somewhere.

8:16What each choice costs

Windows lets the program that opens a file decide how others may share it. The cost is that sometimes you cannot delete your own file, because another program has not allowed it. Unix keeps the name and the object apart, so many things can be replaced while the system is running. The cost is half a gigabyte that vanished from the disk and belongs to no file at all.

And look at how each of those gets resolved. On Windows, one way out is closing the program that holds the file. On Linux, one way to get that disk space back is restarting the service that still has it open. Different causes. Sometimes, the same remedy.

9:11So what does it mean to open a file?

So. The question from the start. What does it mean to open a file? It means you are holding something. The two systems simply hand you different things to hold. Which is why that message never actually said this file cannot be deleted. It said the program that opened it did not agree to let you. And it does know which program. It just did not mention it.
