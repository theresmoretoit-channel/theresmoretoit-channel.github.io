Warum kann Windows eine Datei in Benutzung nicht löschen?

10 Min.2026-09-22

Diese Meldung ist das sichtbare Ende einer viel merkwürdigeren Frage: Was heißt es eigentlich, eine Datei zu öffnen? Denn auf einem anderen Rechner lässt sich dieselbe Datei, genau gleich geöffnet, ohne jeden Einwand löschen.

Zuerst das Nützliche. Windows weiß seit 2009, welches Programm es ist, und es sagt es dir auch — Ressourcenmonitor, Registerkarte CPU, Zugeordnete Handles, Dateinamen eintippen. Nichts zu installieren. Die Leute haben trotzdem weiter ein eigenes Werkzeug geladen, und sie hatten einen Grund.

0:00Die Meldung, die jeder kennt

Du willst eine Datei löschen. Der Rechner sagt, sie sei offen in einem anderen Programm. Nur in welchem, sagt er nicht. Diese Meldung ist das sichtbare Ende einer viel merkwürdigeren Frage. Was heißt es eigentlich, eine Datei zu öffnen? Denn auf einem anderen Rechner lässt sich dieselbe Datei, auf dieselbe Weise geöffnet, ohne jeden Einwand löschen. Dieselbe Datei. Dieselbe Aktion. Zwei völlig verschiedene Antworten.

0:29Welches Programm?

Fangen wir mit dem an, was alle ärgert. Welches Programm? Windows weiß es. Es hat ein Kernel-Objekt für diese offene Datei und kennt den Besitzerprozess. Es könnte ihn benennen. Also schließt du wahllos Programme. Du öffnest den Task-Manager. Du starrst auf eine Prozessliste und erkennst fast keinen davon. Und jahrelang war die Antwort tatsächlich, ein separates Tool herunterzuladen. Unlocker erschien 2005, und unter Windows XP war das die Antwort.

1:02Windows sagt es dir längst

Dann brachte Windows 7 den Ressourcenmonitor. Die Registerkarte CPU. Eine Liste namens Zugeordnete Handles. Tippe den Dateinamen ein. Du bekommst das Programm und die Prozess-ID. Nichts zu installieren. Das gibt es seit 2009.

Die separaten Tools taten aber mehr, als es dir nur zu sagen. Sie konnten das Handle schließen und die Datei freigeben.

1:30Was du beim Öffnen einer Datei ausfüllst

Womit wir zurück bei der Frage wären. Was hat das Programm bekommen, als es die Datei öffnete? Nehmen wir an, ein Player öffnet eine Datei namens movie.mp4. Unter Windows bedeutet das Öffnen einer Datei, zwei Dinge festzulegen. Das erste ist offensichtlich. Was will ich damit machen? Sie lesen. In sie schreiben. Das zweite ist das interessante. Was dürfen alle anderen tun, solange ich sie offen habe? Das ist eine echte Einstellung. Du legst fest, was andere Programme dürfen, solange du sie geöffnet hast. Sie dürfen sie lesen. Sie dürfen auch hineinschreiben. Sie dürfen sie löschen oder umbenennen.

Oder gar nichts davon. Solange ich sie benutze, rührt sie niemand an.

2:16FILE_SHARE_DELETE

Das Flag, das Löschen erlaubt, heißt FILE_SHARE_DELETE. Und Microsofts Dokumentation fügt direkt darunter eine Zeile hinzu. Der Löschzugriff umfasst Löschen und Umbenennen zugleich. Ein Programm, das die Freigabe zum Löschen verweigert, hat also auch das Umbenennen gesperrt.

Und wenn das Programm, das die Datei geöffnet hat, sie nicht erteilt, kann sie sich niemand nehmen.

2:41Eine Freigabeverletzung

Deshalb heißt der Fehler nicht Datei in Benutzung. Er heißt Freigabeverletzung. Die Antwort steckte die ganze Zeit im Namen des Fehlers selbst.

2:53Unter Linux klappt es einfach

Jetzt dasselbe auf einem Linux-Rechner. Ein Player öffnet das Video. Und du tippst rm movie.mp4. Es klappt. Das Video läuft weiter.

Was hat das Programm also bekommen, wenn es die Datei nicht festhält? Das ist die ganze Idee dieses Videos. Der Name ist nicht die Datei.

3:16Ein Name ist nicht die Datei

movie.mp4 ist eine Zeile in einem Verzeichnis. Diese Zeile zeigt auf ein Objekt, in dem die eigentlichen Daten liegen. Wenn ein Programm die Datei öffnet, bekommt es einen Verweis auf das Objekt. Nicht auf die Zeile. Die Datei zu löschen entfernt also die Zeile. Das Objekt bleibt unberührt. Die Handbuchseite sagt es in einem einzigen Satz. Die Datei bleibt bestehen, bis der letzte Dateideskriptor, der auf sie verweist, geschlossen ist.

3:48Fünfhundert Megabyte, die verschwinden

Das klingt abstrakt, bis man es einmal sieht. Ich habe also eine Protokolldatei von fünfhundert Megabyte angelegt und einen Prozess die Datei geöffnet halten lassen. Dann habe ich sie gelöscht. Die Verzeichnisliste zeigt überhaupt nichts. Das Werkzeug, das die Ordnergröße misst, meldet null. Und das Werkzeug, das den freien Platz auf der Platte misst, meldet, dass fünfhundert Megabyte immer noch fehlen. Ein leerer Ordner. Ein halbes Gigabyte weg.

Das passiert oft genug, dass es einen eigenen Befehl gibt, nur um solche Dateien zu finden. Gelöscht, unsichtbar, noch auf der Platte. Und der Platz kommt zurück, sobald dieser eine Prozess die Datei loslässt.

4:34Umbenennen, und eine Grenze

Dasselbe gilt fürs Umbenennen. Verschiebe sie, während sie geöffnet ist, und das Programm merkt es nicht. Das Handbuch ist auch da deutlich. Offene Dateideskriptoren für den alten Pfad bleiben unberührt. Es hat den Namen nie benutzt.

Das hat eine Grenze, die man kennen sollte. Ein laufendes Programm lässt sich nicht an Ort und Stelle überschreiben. Linux weigert sich. Text file busy.

Was geht, ist den Namen zu entfernen und eine neue Datei hinzulegen. Der alte Prozess läuft weiter mit einem Objekt, das keinen Namen mehr hat. Alles später Gestartete bekommt das neue. Damit bestätigt sich dieselbe Idee noch einmal. Vieles lässt sich austauschen, ohne das Objekt selbst anzufassen.

Deshalb kann Linux ein Programm im laufenden Betrieb aktualisieren. Die neue Version bekommst du nur, wenn du es neu startest.

Ist Windows also schlicht schlechter entworfen?

5:36Windows kann dasselbe

Nein. Und das ist der Teil, den kaum jemand kennt. Windows hat einen Weg, genau dasselbe zu tun. Auf NTFS kann Windows ein Löschen im POSIX-Stil anfordern. Microsoft beschreibt, was dann passiert. Der Name verschwindet aus dem sichtbaren Namensraum. Und Anwendungen, die die Datei schon offen hatten, nutzen sie weiter, obwohl der Name, mit dem sie sie öffneten, weg ist. Das ist das Unix-Verhalten. Auf NTFS. Von Microsoft dokumentiert.

Beide Systeme können beides. Was sich unterscheidet, ist die Vorgabe. Das, was du bekommst, wenn du eine Datei öffnest, ohne nachzudenken. Unter Windows bekommst du einen Vertrag. Unter Unix bekommst du einen Verweis auf ein Objekt.

6:31Starten Sie den Computer neu

Was nach einer Frage für Programmierer klingt, bis man diese eine Meldung gesehen hat. Starten Sie den Computer neu, um die Updates abzuschließen.

Angenommen, Windows muss eine Bibliothek ersetzen, die ein Prozess unter dem strengen Vertrag offen hält. Es kann die Datei unter dem Prozess nicht tauschen. Also muss etwas loslassen. Die Anwendung beenden. Den Dienst stoppen. Oder die ganze Sache dem Neustart-Manager überlassen.

7:03Der Neustart-Manager

Der ist ein echter Bestandteil. Er fährt alles der Reihe nach herunter. Windows-Anwendungen, dann Konsolenprogramme, dann Dienste, und den Explorer zuletzt. Danach startet er sie wieder. Und es gibt ihn aus einem Grund, den Microsoft klar ausspricht, in der eigenen Dokumentation. Der Hauptgrund, warum Softwareinstallationen und Updates einen Neustart des Systems verlangen… ist, dass einige der Dateien, die aktualisiert werden, gerade von einer laufenden Anwendung oder einem Dienst benutzt werden.

7:38Aber das ist nicht der ganze Grund

Es wäre zu ordentlich, hier zu enden. Freigaberegeln sind nicht der einzige Grund, warum ein Rechner zu einem Neustart auffordert. Ein Kernel-Update ist etwas anderes. Den Kernel unter sich selbst zu tauschen geht nicht. Linux hat dasselbe Problem, auch wenn Live-Patching einen Neustart manchmal erspart. Die ehrliche Fassung behauptet also weniger als die befriedigende.

Wie Windows mit Dateien in Benutzung umgeht, machte manche Bestandteile im Betrieb schwerer austauschbar, und das hat dazu beigetragen. Denn jede Entwurfsentscheidung hat irgendwo eine Folge.

8:16Was jede Entscheidung kostet

Windows lässt das Programm, das eine Datei öffnet, entscheiden, was andere mit ihr tun dürfen. Der Preis ist, dass du manchmal deine eigene Datei nicht löschen kannst, weil ein anderes Programm es nicht erlaubt hat. Unix trennt Name und Objekt voneinander, so lässt sich vieles austauschen, während das System läuft. Der Preis ist ein halbes Gigabyte, das von der Platte verschwand und zu gar keiner Datei gehört.

Und sieh dir an, wie sich beides jeweils auflöst. Unter Windows ist ein Ausweg, das Programm zu beenden, das die Datei hält. Unter Linux ist ein Weg, den Platz zurückzubekommen, den Dienst neu zu starten, der sie noch offen hat. Verschiedene Ursachen. Manchmal dasselbe Mittel.

9:11Also, was heißt es, eine Datei zu öffnen?

Also. Die Frage vom Anfang. Was heißt es, eine Datei zu öffnen? Es heißt, dass du etwas hältst. Die beiden Systeme geben dir schlicht Verschiedenes in die Hand. Deshalb hat diese Meldung nie wirklich gesagt, dass die Datei nicht löschbar ist. Sie sagte, dass das Programm, das sie geöffnet hat, es dir nicht erlaubt hat. Und es weiß, welches Programm. Es hat es nur nicht erwähnt.
