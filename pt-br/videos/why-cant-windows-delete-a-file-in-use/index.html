Por que o Windows não consegue apagar um arquivo em uso?

10 min2026-09-22

Essa mensagem é a ponta visível de uma pergunta bem mais estranha: o que significa de fato abrir um arquivo? Porque em outro computador o mesmo arquivo, aberto exatamente do mesmo jeito, some sem uma única reclamação.

Primeiro a parte útil. O Windows sabe desde 2009 qual é o programa, e ele te conta — Monitor de Recursos, aba CPU, Identificadores Associados, digite o nome do arquivo. Nada para instalar. Mesmo assim as pessoas continuaram baixando uma ferramenta separada, e tinham um motivo.

0:00A mensagem que todo mundo conhece

Você tenta apagar um arquivo. O computador diz que ele está aberto em outro programa. Mas não diz em qual. Essa mensagem é a ponta visível de uma pergunta bem mais estranha. O que significa de fato abrir um arquivo? Porque em outro computador o mesmo arquivo, aberto igual, some sem uma única reclamação. O mesmo arquivo. A mesma ação. Duas respostas completamente diferentes.

0:29Qual programa?

Comece pela parte que irrita todo mundo. Qual programa? O Windows sabe. Ele tem um objeto de kernel para esse arquivo aberto e sabe qual processo é o dono. Poderia dizer o nome. Então você fecha coisas a esmo. Abre o Gerenciador de Tarefas. Encara uma lista de processos e quase não reconhece nenhum. E por anos a resposta foi mesmo baixar uma ferramenta separada. O Unlocker saiu em 2005, e no Windows XP essa era a resposta.

1:02O Windows já te conta

Depois o Windows 7 trouxe o Monitor de Recursos. A aba CPU. Uma lista chamada Identificadores Associados. Digite o nome do arquivo. Ele te dá o programa e o identificador do processo. Nada para instalar. Está ali desde 2009.

Mas as ferramentas separadas faziam mais do que só te avisar. Elas conseguiam fechar o identificador e liberar o arquivo.

1:30O que você preenche ao abrir um arquivo

O que nos traz de volta à pergunta. O que aquele programa recebeu quando abriu o arquivo? Digamos que um player abra um arquivo chamado movie.mp4. No Windows, abrir um arquivo significa preencher duas coisas. A primeira é óbvia. O que eu quero fazer com ele? Ler. Escrever nele. A segunda é a interessante. O que os outros podem fazer enquanto eu o mantenho aberto? É uma configuração de verdade. Você diz o que outros programas podem fazer enquanto você o segura. Eles podem lê-lo. Também podem escrever nele. Podem apagá-lo ou renomeá-lo.

Ou nada disso. Ninguém encosta nele enquanto eu estiver usando.

2:16FILE_SHARE_DELETE

O sinalizador que permite apagar se chama FILE_SHARE_DELETE. E a documentação da Microsoft acrescenta uma linha embaixo. O direito de apagar abrange apagar e renomear ao mesmo tempo. Então um programa que recusa o compartilhamento de exclusão bloqueou a renomeação também.

E se o programa que abriu o arquivo não concedeu esse direito, mais ninguém pode tomá-lo.

2:41Uma violação de compartilhamento

É por isso que o erro não se chama arquivo em uso. Chama-se violação de compartilhamento. A resposta esteve o tempo todo no nome do próprio erro.

2:53No Linux simplesmente funciona

Agora a mesma coisa numa máquina Linux. Um player abre o vídeo. E você digita rm movie.mp4. Funciona. O vídeo continua tocando.

Então o que aquele programa pegou, se não foi nenhum controle sobre o arquivo? Esta é a ideia inteira do vídeo. O nome não é o arquivo.

3:16Um nome não é o arquivo

movie.mp4 é uma linha num diretório. Essa linha aponta para um objeto que guarda os dados de verdade. Quando um programa abre o arquivo, o que ele recebe é uma referência ao objeto. Não à linha. Apagar o arquivo remove então a linha. O objeto fica intocado. A página do manual diz isso numa única frase. O arquivo continuará existindo até que o último descritor de arquivo que o referencia seja fechado.

3:48Quinhentos megabytes que somem

Parece abstrato até a gente ver acontecer. Então fiz um arquivo de log de quinhentos megabytes e deixei um processo com ele aberto. Depois apaguei. A listagem do diretório não mostra absolutamente nada. A ferramenta que mede o tamanho da pasta diz zero. E a ferramenta que mede o espaço livre no disco diz que quinhentos megabytes ainda estão faltando. Uma pasta vazia. Meio gigabyte sumido.

Isso acontece com frequência suficiente para existir um comando só para achar arquivos assim. Apagados, invisíveis, ainda no disco. E o espaço volta no instante em que aquele processo solta o arquivo.

4:34Renomear, e um limite

A mesma lógica vale para renomear. Mova o arquivo aberto, e o programa nem percebe. O manual também é direto nisso. Descritores abertos do caminho antigo não são afetados. Ele nunca usou o nome.

O que tem um limite que vale a pena conhecer. Um programa em execução não dá para sobrescrever diretamente. O Linux recusa. Text file busy.

O que dá para fazer é desvincular o nome e colocar um arquivo novo ali. O processo antigo segue rodando a partir de um objeto que não tem mais nome nenhum. Quem iniciar depois usa o novo. O que é a mesma ideia de novo, provando a si mesma. Muita coisa dá para substituir sem tocar no próprio objeto.

Por isso o Linux consegue atualizar um programa enquanto ele roda. Você só não fica com a versão nova até reiniciá-lo.

Então o Windows é simplesmente mal projetado?

5:36O Windows faz a mesma coisa

Não. E esta é a parte que quase ninguém conhece. O Windows tem um jeito de fazer exatamente a mesma coisa. No NTFS, o Windows pode pedir uma exclusão no estilo do POSIX. A Microsoft descreve o que acontece então. O nome é removido do espaço de nomes visível. E os aplicativos que já tinham o arquivo aberto seguem usando, mesmo que o nome com que o abriram já não exista. Esse é o comportamento do Unix. No NTFS. Documentado pela Microsoft.

Os dois sistemas fazem as duas coisas. O que difere é o padrão. O que você recebe ao abrir um arquivo sem pensar nisso. No Windows você recebe um contrato. No Unix você recebe uma referência a um objeto.

6:31Reinicie o computador

O que soa como pergunta de programador, até você ter visto esta mensagem específica. Reinicie o computador para concluir a instalação.

Suponha que o Windows precise trocar uma biblioteca que um processo mantém aberta sob o contrato estrito. Ele não pode trocar o arquivo por baixo daquele processo. Então algo precisa soltar. Fechar o aplicativo. Parar o serviço. Ou entregar o trabalho todo ao Gerenciador de Reinicialização.

7:03O Gerenciador de Reinicialização

Que é um componente de verdade. Ele desliga as coisas em ordem. Aplicativos do Windows, depois programas de console, depois serviços, e o Explorador por último. Depois ele os inicia de novo. E ele existe por um único motivo, que a Microsoft diz sem rodeios na própria documentação. O principal motivo pelo qual instalações de software e atualizações exigem reiniciar o sistema… é que alguns dos arquivos que estão sendo atualizados estão em uso por um aplicativo ou serviço em execução.

7:38Mas esse não é o motivo todo

Seria bom demais parar por aí. As regras de compartilhamento não são o único motivo de um computador pedir reinício. Atualizar o kernel é outra coisa. Não dá para trocar o kernel por baixo dele mesmo. O Linux tem o mesmo problema, embora o live patching às vezes evite o reinício. Então a versão honesta promete menos do que a versão satisfatória.

O jeito como o Windows trata arquivos em uso deixou alguns componentes mais difíceis de trocar em execução, e isso contribuiu. Porque toda escolha de projeto tem uma consequência em algum lugar.

8:16Quanto custa cada escolha

O Windows deixa o programa que abre um arquivo decidir o que os outros podem fazer com ele. O preço é que às vezes você não apaga seu próprio arquivo, porque outro programa não permitiu. O Unix mantém o nome e o objeto separados, então muita coisa dá para trocar com o sistema rodando. O preço é meio gigabyte que sumiu do disco e não pertence a arquivo nenhum.

E olhe como cada um dos dois se resolve. No Windows, uma saída é fechar o programa que segura o arquivo. No Linux, um jeito de recuperar esse espaço é reiniciar o serviço que ainda o mantém aberto. Causas diferentes. Às vezes o mesmo remédio.

9:11Então o que significa abrir um arquivo?

Então. A pergunta do começo. O que significa abrir um arquivo? Significa que você está segurando algo. Os dois sistemas simplesmente dão coisas diferentes para você segurar. É por isso que aquela mensagem nunca disse de verdade que o arquivo não pode ser apagado. Ela disse que o programa que o abriu não deu permissão a você. E ele sabe qual programa é. Só não mencionou.
